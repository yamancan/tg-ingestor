# Privacy and correctness review

The source tree and synthetic fixtures were inspected for real conversation data, user-specific filesystem paths, email addresses and credential patterns. Real-export smoke tests run outside the source tree; their inputs, previews and summaries are private artifacts and are not repository fixtures. The fixture names, participant IDs and conversation contents in this repository are fabricated; external links use the reserved `example.test` domain.

## Findings addressed

- **Medium — full validation did not compare conversation metadata with its source.** A modified title, date range, participant list or single-chat original-input checksum could pass validation after derived documents were refreshed. Full validation now reconstructs and compares those fields. Synthetic tampering tests cover each field separately.
- **Low — a citation could become Markdown image syntax.** Placing `!` directly before an evidence marker previously turned the generated local citation into an image. The renderer now escapes that prefix while preserving the citation, ordinary punctuation and the original JSON body. This was a local rendering defect, not a demonstrated remote-data exfiltration path.
- **High — manifest navigation was insufficiently validated.** A symlinked manifest could disclose metadata from a file outside the package. The manifest now uses guarded file access and validates fixed paths, IDs, settings, fragment structure and the exact derived job graph before package-directed access. Tests cover symlinked files/directories, traversal and forged jobs.
- **Medium — generated summaries could contain active HTML or image syntax.** A synthetic model draft containing remote image markup was previously accepted into rendered Markdown. Rendering now escapes HTML and authored links/images while preserving generated local evidence links. Raw JSON bodies remain unmodified.
- **Medium — special files and unbounded input could block or exhaust processing.** A FIFO source previously hung waiting for a writer. File reads now reject special files and enforce byte limits before parsing. JSON depth, duplicate keys, non-finite numbers and configuration bounds are checked. Regression tests use timeout-guarded subprocesses and sparse oversized files.
- **High — unrelated chats copied into a selected-chat package.** `prepare --chat` previously archived the entire account-wide input, including other conversations and account metadata. New packages archive only the selected chat object. Single-chat inputs retain byte-for-byte preservation. Regression coverage checks every generated file for unselected synthetic markers.
- **High — legitimate Unicode text failed validation.** Reading JSONL with `splitlines()` treated Unicode paragraph/line separators inside message strings as record boundaries. Validation now splits only on LF and preserves those characters. A regression test checks reconstruction with multiple Unicode separators.
- **Medium — identities appeared in ordinary preparation logs.** The preparation report now emits a participant count rather than participant names and IDs. Identity metadata remains in the private lossless package, as required for conversation context.
- **Medium — source metadata could render active Markdown.** Sender metadata is now fenced as JSON, and conversation titles are escaped. Text remains fenced. This prevents a source display name or title from becoming a rendered tracking image or HTML element.
- **Medium — private output could be accidentally staged.** Every generated package now has its own ignore rule, including custom output directories. Root ignore rules also cover common export, session and credential files. Real exports and outputs default outside the source repository.
- **Low — Python bytecode exposed local usernames through embedded paths.** Generated bytecode caches were removed. Documented test commands use `python3 -B`; caches remain ignored if recreated by other commands.

## Remaining limitations

- This is a lossless preparation and summarization tool, not an anonymizer. Generated conversation packages retain names, IDs and personal information present in source text. An ignored directory is not safe to publish merely because Git ignores it.
- Citation and coverage validation checks references, hashes and acknowledged input jobs. It cannot prove that a model understood every message or that a summary is factually correct. Evidence review is still necessary.
- Token counts are character-based estimates. Preparation and full validation load JSON into memory; large-input success does not establish a universal memory limit.
- Automated scans detect selected patterns, not every possible form of personal information. Keep only reviewed synthetic examples in this source tree and inspect any future files before publication.
- File checks assume a private directory and a single writer; they do not provide isolation against concurrent filesystem mutation by another process with the same access. See [SECURITY.md](SECURITY.md) for the threat model and resource limits.

## Verification scope

The automated suite covers synthetic preservation, Unicode, malformed input, bounded splitting, hierarchical summaries, resume/correction behavior, corruption, file access and rendering. Run it with `python3 -B -m unittest discover -s tests -v`.

A local Gitleaks 8.30.1 directory scan with redacted output found no secret-pattern matches in the reviewed working tree. This is not a comprehensive personal-information detector. No Git metadata was present at review time, so commit history and remote settings were not audited. There are no third-party Python runtime dependencies; this review did not certify the Python installation or host application against all vulnerabilities.

An open-source license still needs to be chosen. Recheck the exact contents and history before future releases; the source review does not cover later commits automatically.

The September 8 source review found no secret-pattern matches and no matches against long identity or message-text markers from the private smoke-test exports. The metadata and citation fixes passed the synthetic suite. Publication exclusions are also tested with synthetic paths against Git itself. Automated tests and secret scanning should be added to CI for future changes.

## Clean history and staging

There was no previous Git history to rewrite. The repository starts with one source-only initial commit. Its author identity uses a public GitHub username and an ID-based noreply address rather than a private email or full name. Global Git identity settings are not changed.

The root ignore file excludes files by default and explicitly allows reviewed documentation, skill code, tests and the synthetic fixture. Private data, generated packages, environments, caches and local agent configuration remain ignored even under the allowed source trees. These rules do not sanitize an allowed file's contents or defeat forced staging. Scan the exact staged tree and all commits before a public push.

The public repository is [yamancan/tg-ingestor](https://github.com/yamancan/tg-ingestor). Private vulnerability reports use the channel linked in SECURITY.md. No CI workflow or selected license is present yet. Future commits and changes to repository settings require their own review.

Publication includes source code, documentation and synthetic tests only. Real exports and generated conversation packages remain outside the repository.
